# TSK Laser — лендінг лазерного обладнання

Статичний сайт (HTML + CSS + JS, без збірки та залежностей). Структура блоків
відповідає Розділу Е технічного завдання.

## Структура

```
index.html              головна, порядок блоків за Розділом Е ТЗ
thank-you.html          сторінка подяки (А-13), закрита від індексації
privacy.html            політика конфіденційності — ЗАГОТОВКА для юриста
404.html                сторінка помилки
robots.txt              індексація; thank-you.html закрито
assets/css/style.css    стилі, токени дизайну, адаптив
assets/js/calc.js       калькулятор окупності (Б-2) + коефіцієнти
assets/js/quiz.js       квіз-підбір: 2 питання + контакти (Б-3)
assets/js/main.js       меню, FAQ, модалки, валідація й надсилання форм
assets/img/             оптимізовані фото обладнання + og-cover.jpg
serve.js                локальний статичний сервер
ІНСТРУКЦІЯ.md           інструкція для замовника: хостинг, доступи, що лишилось
.claude/launch.json     конфіг дев-сервера
```

## Локальний запуск

```bash
node serve.js
```

Далі http://localhost:8787. Порт задається аргументом: `node serve.js 3000`.

## Незаповнені дані

Немає. Механізм маркерів (`class="todo"`, клас `is-draft`, режим `?draft=1`)
прибрано разом з останніми вісьмома позначками — вони збивали з пантелику на
живому сайті. Порожніх місць у розмітці не лишилось.

Два тексти на сторінці політики написані за замовчуванням і потребують
підтвердження юриста, хоча в коді нічим не позначені:

- **строк зберігання** — стоїть 3 роки з дня останнього контакту;
- **перелік отримувачів даних** — Make.com, Google (GTM + Analytics),
  хостинг-провайдер. Це фактичний стек сайту; якщо заявки підуть ще кудись,
  список треба доповнити.

Розділ «Публічна оферта» видалено разом із посиланням на нього у підвалі:
документа не існує, а порожній розділ гірший за його відсутність. Коли
оферту напишуть, повернути треба обидва.

### Логотипи клієнтів

Чотири з дев'яти — справжні вектори (`.svg`, без растру всередині), тож
різкі на будь-якому екрані. Їм задано `filter: brightness(0)`, щоб
різнокольорові оригінали читалися однаково на світлій плитці.

П'ять растрових замовник надав знімками з чужих сайтів — 70–144 px завширшки.
Три з них мають **вбудований фон**, а не прозорий, і на плитці `#f4f5f7`
світилися прямокутником: у `choice` і `gavryliv-sons` фон чисто білий
(255) — ясніший за плитку, у `promspetsbud` сірий (~220) — темніший.

Прибрано на рівні відображення, без перегенерації файлів:

- `.clients__item--solid img { mix-blend-mode: multiply }` — білий фон
  множиться на колір плитки й дає рівно колір плитки, тобто зникає;
- `.clients__item--grey img { filter: brightness(1.16) }` для
  `promspetsbud`: multiply сам по собі зробив би сіру плашку ще темнішою,
  тому фон спершу витягується до білого (255/220 ≈ 1.16).

Заміряно на композиті: фон усіх трьох відхиляється від кольору плитки не
більше ніж на 1.4 з 255 — око такого не бачить, — а контраст чорнила лого
лишається 177–196.

**Чого це не лікує.** П'ять растрових логотипів показуються майже 1:1 до
свого пікселного розміру, тож на екранах 2x і 3x вони м'які. Запас
різкості 0.5–0.62 замість 1.0. Вищої роздільності в оригіналах немає —
у папці `Логотипи клієнтів/` лежать ті самі маленькі файли. Лікується
тільки новими файлами від замовника: `.svg` або PNG від 400 px завширшки.

### Прев'ю посилань

`og:image` і `og:url` — єдині місця на сайті з повною адресою. Роботи
Telegram, Viber і Facebook не виконують скрипти й не знають, звідки прийшло

## Прийом заявок

П'ять форм: фінальний CTA, універсальна модалка, тестовий зразок, квіз,
плюс калькулятор (не форма). Усі валідуються на клієнті й після успіху ведуть
на `thank-you.html`, як вимагає В-5.

Заявки йдуть на вебхук Make.com — `ENDPOINT` у [assets/js/main.js](assets/js/main.js),
зараз `hook.eu2.make.com/n6fbfan75izqsayuyg4p73bsvdkwixln`.
CORS у Make налаштований (`allow-origin: *`), тож JSON шлеться напряму
з браузера, без обхідних шляхів.

### Самоперевірка після хостингу

`САЙТ/?leadtest=1` показує панель із кнопкою, яка шле на той самий вебхук
позначену тестову заявку й виводить код відповіді. Це відповідь на реальну
проблему: зламане надсилання ніяк себе не проявляє — форма мовчить, людина
йде, ніхто не дізнається. Панель робить збій видимим за один клік і називає
причину (410 — сценарій вимкнено, мережева помилка — блокувальник тощо).

Кнопка, а не автозапуск: відкриття посилання не має нічого слати в CRM.

### Три запобіжники проти мовчазної втрати заявки

1. `response.ok` — `fetch` не кидає помилку на 4xx/5xx, тож без перевірки
   людина бачила б сторінку подяки при мертвій інтеграції.
2. Захват `submit` у `<head>` + мітка `data-lead-js`, яку ставить main.js.
   Якщо main.js не завантажився, форма зробила б звичайний GET-сабміт:
   сторінка перезавантажується, заявка зникає без сліду. Тепер нативна
   відправка блокується, а внизу зʼявляється смуга з телефоном.
3. `?v=3` на посиланнях зі стилями й скриптами — щоб після оновлення сайту
   хостинг не віддавав старий `main.js` зі старою адресою вебхука з кешу.
   **Змінюючи ENDPOINT, підніміть і цей номер.**

**Сценарій у Make має бути увімкнений.** Поки він вимкнений, вебхук
відповідає `410 There is no scenario listening`, і сайт показує форму
з прямими контактами замість сторінки подяки.

Відповідь перевіряється через `response.ok`: `fetch` не кидає помилку на
4xx/5xx, тому без цієї перевірки заявка зникала б, а людина бачила б
сторінку подяки. При збої payload лишається в консолі браузера.

Що приходить у payload: усі поля форми, `form_source` (з якого блоку заявка —
основа сегментації в CRM за В-5), а для квіза ще `quiz` з відповідями
й `recommended`.

**Телефон валідується як український** і нормалізується перед відправкою:
як би його не ввели, у CRM приходить один формат `+380671234567`.

Код `+380` винесено з інпута окремим елементом `.field__phone-code` —
у самому полі лишаються тільки 9 абонентських цифр. Це не косметика:
поки код був усередині значення, його неможливо було відрізнити від
набраного людиною, і `0671234567` перетворювалося на `+380 06 712 34 56`.
Тепер маска форматує просто під час набору, бо неоднозначності немає. Приймається `+380` і ще
9 цифр, перша з яких 3–9 — це пропускає і мобільні, і стаціонарні
(Київ 044, Львів 032), але відсікає надто довгі набори й чужі коди країн.
Логіка — `normalizePhone()` в [assets/js/main.js](assets/js/main.js).

**На інпутах не має бути `maxlength`.** Обмеження довжини живе тільки в масці.
Браузер застосовує `maxlength` до того, як спрацює обробник `input`, тому
автозаповнення й вставка повного номера обрізалися з хвоста: телефон
підставляв `+380671234567`, атрибут `maxlength="12"` лишав `+38067123456`,
маска знімала код країни й показувала `67 123 45 6` — на цифру коротше, зате
цілком правдоподібно. На телефоні номер здебільшого підставляється, а не
набирається, тому ламалося саме там, а на ПК не помічалося.

Маска сама ріже до 9 абонентських цифр на кожній події `input`, тож заборона
«ввести більше, ніж потрібно» лишається — перевірено набором 14 цифр підряд.

`autocomplete="tel-national"`, а не `tel`: у полі лежить тільки національна
частина номера, код країни стоїть поруч окремим елементом.

### Файли креслень

Форма тестового зразка (Б-5) приймає DXF, DWG, PDF, JPG, PNG до 15 МБ і
перевіряє тип і розмір на клієнті. Щоб файли реально доходили, обробник має
приймати `multipart/form-data` — поточний код надсилає JSON і передає лише
імʼя й розмір файлу.

## Калькулятор окупності

Уся арифметика й коефіцієнти — у `CONFIG` на початку
[assets/js/calc.js](assets/js/calc.js). Формула взята з Б-2 ТЗ:

```
економія = поточні витрати − (електроенергія + газ + витратники + оператор)
окупність = ціна верстата ÷ економія
```

**Числа в `CONFIG` — реальні** (бриф 4.1 і 4.2): тариф 11 грн/кВт·год,
витратники 25 грн/год, оператор 35 000 грн/міс (середина наданого діапазону
30–40 тис.), різка на стороні 75 грн/м. `provisional: false`, тому
попередження про орієнтовність у результаті не показується.

**Робочий газ — окреме поле форми**, а не усереднене значення: розкид за
брифом 4.2 понад 10x (повітря 5–20, кисень 25–70, азот 120–300 грн/год),
і це найсильніше рухає підсумок. Якщо користувач не обрав газ, береться
середнє 70 грн/год і показується попередження.

Ціна тепер береться з матриці `PRICE[матеріал][товщина]`, а не за потужністю —
так її дав технічний відділ. Для комбінацій, яких у матриці немає (`null`),
підставляється найближча відома, і користувач бачить попередження.

**Що показує калькулятор на цих даних:** для сценаріїв із кейсів замовника
(аутсорс 168–315 тис. грн/міс) окупність виходить 10–13 місяців. Для окупності
за 6 місяців потрібні витрати на аутсорс близько 266 000 грн/міс.

## Конверсії та аналітика

**Google Tag Manager `GTM-WZQLL2J5`** підключений на всіх чотирьох сторінках:
контейнер у `<head>` одразу після `charset`, `noscript` — першим елементом
у `<body>`.

Це цільова схема з Г-4: усі теги живуть усередині контейнера, прямих вставок
у код більше робити не треба. Перевірено, що контейнер вантажиться й уже
тягне GA4 `G-6SVMDVH4VT`.

**Що лишилось налаштувати всередині GTM** (в інтерфейсі, не в коді) —
з тригером тільки на `/thank-you.html`: дія-конверсія Google Ads, подія
`Lead` у Meta, `SubmitForm` у TikTok, `form_submit` у GA4.

Ключове правило Г-1: конверсія має спрацьовувати **тільки** на сторінці
подяки. На головній не повинно спрацьовувати жодної — інакше Smart Bidding
вважає конверсією кожен візит.

**Банер згоди на cookie не зроблено.** Аналітика вже збирає дані, тому за
законом він потрібен — зазначено в політиці конфіденційності як відкрите
питання до юриста.

## Дрібниці

- Секції розкриваються при скролі; якщо `IntersectionObserver` не спрацював
  за 2.5 с, контент показується примусово.
- `prefers-reduced-motion` вимикає анімації.
- Адаптив: 1080px → дві колонки, 900px → бургер, 640px → одна колонка.
  Перевірено на 320 / 360 / 375 / 390 / 414 px — горизонтального скролу
  немає на жодній ширині. Широкі таблиці скроляться всередині себе.

  **Як перевіряти мобільну верстку.** Панель браузера в Claude Code не
  застосовує вузькі вьюпорти надійно — вона віддає ~620 px незалежно від
  запиту, через що дефекти лишаються непоміченими. Достовірний спосіб —
  вкласти сайт в iframe фіксованої ширини: медіазапити всередині нього
  реагують на його власну ширину.

  **Шрифт полів вводу на мобільному — рівно 16px.** iOS Safari масштабує
  сторінку при фокусі на полі зі шрифтом меншим за 16px і назад не повертає:
  людина тицяє в поле й лишається на збільшеній сторінці з обрізаною версткою.
  Медіазапит до 900px піднімає всі поля до 16px. Забороняти масштабування
  через `maximum-scale` не можна — це ламає доступність.

  До 360px обгортка номера має вужчі відступи: при 16px повний номер інакше
  довший за поле на кілька пікселів і останні цифри ховаються за краєм.

  **Пастка, через яку виникали всі переповнення:** елемент CSS-сітки має
  `min-width: auto` і не звужується менше за min-content вмісту. Якщо
  всередині таблиця з `min-width` або зображення — сітка розпирає сторінку.
  Тому в проєкті скрізь `minmax(0, 1fr)` замість голого `1fr`, а контейнери
  з таблицями мають явний `min-width: 0`.
- Основна кнопка сайту помаранчева (В-3), сині — другорядні.

## Передача замовнику

Для замовника — окремий файл [ІНСТРУКЦІЯ.md](ІНСТРУКЦІЯ.md): як захостити,
що перевірити після хостингу, куди приходять заявки, що робити, якщо вони
не приходять, і які доступи треба передати разом із сайтом.

Сайт не має жодного абсолютного шляху, тому однаково працює і в корені
домену, і в підпапці (GitHub Pages виду `user.github.io/tsk/`).
