# TSK Laser — лендінг лазерного обладнання

Статичний сайт (HTML + CSS + JS, без збірки та залежностей). Структура блоків
відповідає Розділу Е технічного завдання.

## Структура

```
index.html              головна, порядок блоків за Розділом Е ТЗ
thank-you.html          сторінка подяки (А-13), закрита від індексації
privacy.html            політика конфіденційності — ЗАГОТОВКА для юриста
assets/css/style.css    стилі, токени дизайну, адаптив
assets/js/calc.js       калькулятор окупності (Б-2) + коефіцієнти
assets/js/quiz.js       квіз-підбір, 7 кроків (Б-3)
assets/js/main.js       меню, FAQ, модалки, валідація й надсилання форм
assets/img/             оптимізовані фото обладнання + og-cover.jpg
serve.js                локальний статичний сервер
.claude/launch.json     конфіг дев-сервера
```

## Локальний запуск

```bash
node serve.js
```

Далі http://localhost:8787. Порт задається аргументом: `node serve.js 3000`.

## Незаповнені дані

Усі місця, куди потрібні дані від замовника, позначені в коді класом `todo` і
підсвічені на сторінці помаранчевою рамкою. Знайти всі одразу:

```bash
grep -rn 'class="todo"' *.html
```

Зараз таких місць 10: `index.html` — 1, `privacy.html` — 7, `thank-you.html` — 2.
Було 87 — решту закрито даними з заповненого брифу (серпень 2026).

**Кожен маркер, що лишився, справді чекає даних** — застарілих немає.
Що саме: галузь і обладнання для підписів під логотипами клієнтів (А-5),
юридичні тексти крім реквізитів (розділ 11), відеозйомка (Б-9).

Блоки фінансування та лізингу прибрано на прохання замовника, тому
відповідні маркери зникли разом із ними.

| `logo-dark-text.png` | логотип для світлого тла (в розмітці поки не використовується) |
| `favicon.png` | іконка вкладки, 256×256 |

Логотип узято з `Лого/main/white text/without bg.png` (прозоре тло), фавікон —
зі скороченої версії на темному квадраті. Оригінали лого в `.gitignore`.

Оптимізація фото: `sips -Z 1200 -s format jpeg -s formatOptions 82`.
Разом усі ассети — 1,3 МБ.

**Каталожні рендери зняті на білому тлі**, тому контейнери під них зроблено
світлими (`.product__media--photo`) з `mix-blend-mode: multiply` — інакше на
темному сайті вони читалися б як яскраві прямокутники.

**`lineup.png` — виняток:** у нього прозоре тло (62% пікселів), тому він лягає
прямо на темний фон без підкладки. Розкладка першого екрана — дві колонки:
текст ліворуч, техніка праворуч. Кадр широкий (2,3:1), тож на екранах від
901 px він виходить у вільний правий відступ сторінки, щоб не виглядати
дрібним; `.hero` має `overflow: hidden`, тому скролу це не створює.
До 900 px колонки складаються в одну, фото йде під текстом.

Alt-описи заповнені за формулою ТЗ (Розділ Д): тип + модель + потужність.

## Прийом заявок

П'ять форм: фінальний CTA, універсальна модалка, тестовий зразок, квіз,
плюс калькулятор (не форма). Усі валідуються на клієнті й після успіху ведуть
на `thank-you.html`, як вимагає В-5.

Заявки йдуть на вебхук Make.com — `ENDPOINT` у [assets/js/main.js](assets/js/main.js).
CORS у Make налаштований (`allow-origin: *`), тож JSON шлеться напряму
з браузера, без обхідних шляхів.

**Сценарій у Make має бути увімкнений.** Поки він вимкнений, вебхук
відповідає `410 There is no scenario listening`, і сайт показує форму
з прямими контактами замість сторінки подяки.

Відповідь перевіряється через `response.ok`: `fetch` не кидає помилку на
4xx/5xx, тому без цієї перевірки заявка зникала б, а людина бачила б
сторінку подяки. При збої payload лишається в консолі браузера.

Що приходить у payload: усі поля форми, `form_source` (з якого блоку заявка —
основа сегментації в CRM за В-5), а для квіза ще `quiz` з відповідями
й `recommended`.

**Телефон валідується як український** і нормалізується перед відправкою:
як би його не ввели (`0671234567`, `+38 (067) 123-45-67`, `671234567`),
у CRM приходить один формат `+380671234567`. Приймається `+380` і ще
9 цифр, перша з яких 3–9 — це пропускає і мобільні, і стаціонарні
(Київ 044, Львів 032), але відсікає надто довгі набори й чужі коди країн.
Логіка — `normalizePhone()` в [assets/js/main.js](assets/js/main.js).

### Файли креслень

Форма тестового зразка (Б-5) приймає DXF, DWG, PDF, JPG, PNG до 15 МБ і
перевіряє тип і розмір на клієнті. Щоб файли реально доходили, обробник має
приймати `multipart/form-data` — поточний код надсилає JSON і передає лише
імʼя й розмір файлу.

## Калькулятор окупності

Уся арифметика й коефіцієнти — у `CONFIG` на початку
[assets/js/calc.js](assets/js/calc.js). Формула взята з Б-2 ТЗ:

```
економія = поточні витрати − (електроенергія + газ + витратники + оператор)
окупність = ціна верстата ÷ економія
```

**Числа в `CONFIG` — реальні** (бриф 4.1 і 4.2): тариф 11 грн/кВт·год,
витратники 25 грн/год, оператор 35 000 грн/міс (середина наданого діапазону
30–40 тис.), різка на стороні 75 грн/м. `provisional: false`, тому
попередження про орієнтовність у результаті не показується.

**Робочий газ — окреме поле форми**, а не усереднене значення: розкид за
брифом 4.2 понад 10x (повітря 5–20, кисень 25–70, азот 120–300 грн/год),
і це найсильніше рухає підсумок. Якщо користувач не обрав газ, береться
середнє 70 грн/год і показується попередження.

Ціна тепер береться з матриці `PRICE[матеріал][товщина]`, а не за потужністю —
так її дав технічний відділ. Для комбінацій, яких у матриці немає (`null`),
підставляється найближча відома, і користувач бачить попередження.

**Що показує калькулятор на цих даних:** для сценаріїв із кейсів замовника
(аутсорс 168–315 тис. грн/міс) окупність виходить 10–13 місяців. Для окупності
за 6 місяців потрібні витрати на аутсорс близько 266 000 грн/міс.

## Конверсії та аналітика

**Google Tag Manager `GTM-WZQLL2J5`** підключений на всіх трьох сторінках:
контейнер у `<head>` одразу після `charset`, `noscript` — першим елементом
у `<body>`.

Це цільова схема з Г-4: усі теги живуть усередині контейнера, прямих вставок
у код більше робити не треба. Перевірено, що контейнер вантажиться й уже
тягне GA4 `G-6SVMDVH4VT`.

**Що лишилось налаштувати всередині GTM** (в інтерфейсі, не в коді) —
з тригером тільки на `/thank-you.html`: дія-конверсія Google Ads, подія
`Lead` у Meta, `SubmitForm` у TikTok, `form_submit` у GA4.

Ключове правило Г-1: конверсія має спрацьовувати **тільки** на сторінці
подяки. На головній не повинно спрацьовувати жодної — інакше Smart Bidding
вважає конверсією кожен візит.

**Банер згоди на cookie не зроблено.** Аналітика вже збирає дані, тому за
законом він потрібен — зазначено в політиці конфіденційності як відкрите
питання до юриста.

## Дрібниці

- Секції розкриваються при скролі; якщо `IntersectionObserver` не спрацював
  за 2.5 с, контент показується примусово.
- `prefers-reduced-motion` вимикає анімації.
- Адаптив: 1080px → дві колонки, 900px → бургер, 640px → одна колонка.
  Перевірено на 320 / 360 / 375 / 390 / 414 px — горизонтального скролу
  немає на жодній ширині. Широкі таблиці скроляться всередині себе.

  **Як перевіряти мобільну верстку.** Панель браузера в Claude Code не
  застосовує вузькі вьюпорти надійно — вона віддає ~620 px незалежно від
  запиту, через що дефекти лишаються непоміченими. Достовірний спосіб —
  вкласти сайт в iframe фіксованої ширини: медіазапити всередині нього
  реагують на його власну ширину.

  **Пастка, через яку виникали всі переповнення:** елемент CSS-сітки має
  `min-width: auto` і не звужується менше за min-content вмісту. Якщо
  всередині таблиця з `min-width` або зображення — сітка розпирає сторінку.
  Тому в проєкті скрізь `minmax(0, 1fr)` замість голого `1fr`, а контейнери
  з таблицями мають явний `min-width: 0`.
- Основна кнопка сайту помаранчева (В-3), сині — другорядні.
